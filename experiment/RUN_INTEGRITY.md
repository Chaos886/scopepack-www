# 保存结果与避免混用实验

[首页](../README.md) · [模型运行](LOCAL_INFERENCE.md) · [演绎评测](DEDUCTION.md)

准备请求、评分、统计和推理各有自己的记录。文件哈希用于绑定实际文件，**不会证明预测真的来自某个模型**。

## 输出保护

- `prepare` 遇到已有 requests.jsonl、context_diagnostics.jsonl 或 manifest.json 时拒绝写入。
- `evaluate` 遇到已有 scores.jsonl、summary.json 或 evaluation_manifest.json 时拒绝写入。
- 可使用含其他文件的运行目录，但不能覆盖上述已有产物。检测到上次部分写入也会停止；建立新目录并保留旧文件进行排查。
- 最终文件以排他创建模式打开，避免检查后覆盖已存在的同名文件。这不是跨多个文件的事务；写入故障仍可能留下部分文件。
- 本地运行器只用 `--resume` 恢复原运行；其 journal 是恢复依据，不能删除失败记录后重新计分。

不再通过“换参数但使用原输出目录”的方式重做实验。每个模型、数据/提示/预算设置或生成重复都应有独立运行目录。

## 请求矩阵检查

方法必须已实现且不重复；预算必须为非负整数且不重复。相同 sample / method / budget 不能用不同 request ID 重复加入。请求不能为空，一个文件只能使用一种预算单位。

推理前和评分前都检查这些约束。评分进一步核对实际 messages 与 selected_ids 一致；full 必须确实包含全部句子，none 必须为空文档，两者 budget 都为 0。

## 评分身份清单

评分后额外生成 `evaluation_manifest.json`：

| 字段 | 含义 |
|---|---|
| dataset_sha256 | 评分时的数据文件字节哈希，包含金标 |
| requests_sha256 / predictions_sha256 | 实际请求与预测文件哈希 |
| scores_sha256 | 本次评分输出哈希 |
| code_sha256 | 原型、数据校验及演绎模块代码哈希 |
| prediction_run_id | 本地运行器传入的统一运行身份；旧式导入可能为 null |
| prediction_request_hashes_complete | 所有已提供预测是否都有 request_sha256；无预测时为 false |
| planned_requests / supplied_predictions / missing_predictions | 计划、已保存预测、完全缺失行数 |
| budget_unit | 本次统一预算单位 |

只要预测文件有一条提供 run_id，其他已提供的预测也必须带相同的非空 run_id；混入另一次运行或只给部分行标注会被拒绝。完全没有 run_id 的旧式外部预测仍兼容，但无法自动检测跨运行混用，manifest 会保留这个限制。

已保存 `output:null` 是失败记录，不是 missing；它仍计零分。真正缺失行同样留在计划分母里。不要只对成功返回的题求平均。

## 选择效率的内部检查

新增一次 `select` 调用内的渲染成本缓存，同一组句子只渲染和计数一次。缓存不跨问题、不跨方法、不跨预算共享；需要确定性的计数器，不改变预算定义或选择规则。

2026-10-12 的本地软件核验：60 道合成演绎题 × 4 个受约束方法 × 3 个预算，共 720 个选择结果。优化前后选中句子和依赖边的汇总指纹完全一致。正则计数器调用由 597,431 次降至 100,577 次，减少约 83.2%。单次本机耗时分别约 17.38 秒与 3.50 秒，仅作工程诊断，未做重复测量或控制环境。

这些数字使用正则单元和合成输入，**不是真实 tokenizer 测量、LLM 推理加速或论文方法优势**。真实效率实验仍须完整记录检索、预测依赖、选择、tokenizer、生成及重试开销。

新增 7 项测试覆盖已有/部分输出保护、无效矩阵、重复题与混合单位、混合 run_id、评分身份哈希和成本缓存。全套 46 项软件测试通过；未执行真实模型调用。
