# Benchmark 是否评估 LLM 的演绎能力？

[首页](../README.md) · [英文实验设计补充](../DEDUCTION_STUDY.md) · [模型运行](LOCAL_INFERENCE.md)

**原版只间接涉及演绎，不能单独测量演绎能力；本次增加了可执行的受控演绎诊断，尚未得到真实 LLM 成绩。** 原版 8 个软件样例主要检查条件、时间、引用和答案匹配；即使答对，也可能是直接抽取、猜测或记忆。新模块为事实与规则定义明确语义，用符号程序核对结论及引用支持，帮助分析上下文压缩损害了哪一层。

## 1. 测量什么，以及边界在哪里

| 层次 | 操作化定义 | 能说明什么 |
|---|---|---|
| 直接读取 | 深度 0，结论作为事实给出 | 抽取/格式控制，不计作多步推理证据 |
| 前向演绎 | 深度 1–4，满足规则全部前提后得到结论 | 在指定受控语义下应用和组合规则的表现 |
| 否定与未知 | 明确推导出否定才是 contradicted；两边都推不出则拒答 | 区分否定与信息不足，避免把缺前提当否定 |
| 证据支持 | 引用的句子本身可推导出所答结论 | 可检查的证明支持证书，不等于模型内部推理过程 |
| 压缩保留 | 从实际保留的句子中还能推出完整输入的结论 | 前提/规则是否在压缩中丢失 |

当前语义是**有限、已实例化、有显式否定的合取前向规则系统**：每条规则只在所有前提都成立时触发；没有逆命题、逆否推理、缺省否定、量词、析取或不一致理论推理。该形式片段内的结论可以可靠核验，但不能称作“完整一阶逻辑能力”“通用推理能力”或“自然网页理解能力”。

例如：事实“已验证”“已付款”；规则“已验证且已付款 → 符合资格”“符合资格 → 可以退款”。能推导“可以退款”。若缺少“已付款”，结果是未知，不能推出“不能退款”。这段是中文解释；实际输入使用统一英文模板和无现实含义的随机属性名。

## 2. 新增数据与公平性

[deduction_demo.jsonl](deduction_demo.jsonl) 含 **60 道合成开发题**：4 个词汇/排列家族 × 5 个深度（0–4）× 3 个配对世界（entailed / contradicted / unknown），三种标签各 20 题。每个世界都有 3 份虚构来源文档，全部标记为软件夹具。

同一题族保持词汇、问题、句子数量与排列种子一致：修改末端结论得到明确否定世界；将必要起始事实替换为无关事实得到未知世界。否定世界也会同步调整一条不可触发的诱饵规则，所以这是配对世界设计，**不是只改一个 token 的严格最小反事实**。

每个世界都有逆命题诱饵、没有事实起点的循环、显式否定干扰；部分模板使用必须显式满足的否定前提。正反目标均在文本中出现，避免“看到某个结论字样就答”的简单捷径。这个设计仍有模板规律，不能保证排除所有表面捷径；正式评估须增加新模板、改写、领域迁移和独立人工核验。

`deduction` 字段保存符号规则、标签、深度及配对关系，**只用于数据校验与评测**。`public_input()` 只提供 question/documents；压缩器和答案模型都看不到该字段或 gold。自然语言句子和符号规则逐条精确核对，防止程序验证了另一个问题。此能力只适用于此受控模板，不是任意网页到逻辑的可靠解析器。

所有 60 题均为 `dev`，不冒充冻结测试集。家族聚类将各深度与标签变体绑定；本套仅 4 簇，统计区间会非常不稳定。换随机种子仅改变词汇/排列，不能算新推理模板或领域外泛化。后续训练/开发/测试必须按模板家族隔离，不能靠换 seed 宣称无泄漏。

## 3. 如何运行

从仓库根目录执行；以下离线命令无需模型依赖：

```bash
# 核对结构、文本与符号规则一致性、答案、全部最小充分证据集合
python experiment/deduction.py inspect --data experiment/deduction_demo.jsonl

# 准备上下文与请求；默认正则预算仅用于软件联调
python experiment/prototype.py prepare --data experiment/deduction_demo.jsonl --out work/deduction_prepared --methods full none bm25 neighbors closure --budgets 128 256 512

python -m unittest discover -s experiment -p "test_*.py" -v
```

这个矩阵共 `60 × (2 + 3 × 3) = 660` 条待执行请求。**prepare 不生成答案，也不产生模型分数。** 正式 token 实验必须在 prepare 时添加 `--tokenizer` 并采用与答案模型相同的 tokenizer。

首轮先使用 [本地模型指南](LOCAL_INFERENCE.md) 的运行器执行 10 条请求。运行器默认上限为 10，不会自动跑完 660 条。三类结论协议已写进问题，系统提示和 JSON 输出结构不变：

```json
{"answer":"entailed","citations":["D1:s1","D2:s1"],"abstain":false}
```

上例只说明格式，不是有效真实预测。明确否定时 answer 为 `contradicted`；未知时 `answer=""`、`citations=[]`、`abstain=true`。缺失回复、格式错误仍留在分母，不自动修复或重问。

有了实际运行输出后：

```bash
python experiment/prototype.py evaluate --data experiment/deduction_demo.jsonl --requests work/deduction_run/requests.jsonl --predictions work/deduction_run/predictions.jsonl --out work/deduction_run/evaluation

python experiment/deduction.py report --scores work/deduction_run/evaluation/scores.jsonl --out work/deduction_run/diagnostic
```

始终使用运行器保存的请求子集评分；10 条联调通常不构成完整方法/配对矩阵，不能用于主比较。完整执行后，可继续使用已有 `analyze.py` 比较 answer_em / joint_exact_evidence 的成对差值；它尚不对新增演绎指标计算 bootstrap。新报告包含逐深度、逐标签、配对世界和失败计数的 JSON，以及可阅读的 Markdown；拒绝覆盖已有输出目录。

## 4. 分数怎么读

| 新字段/指标 | 分子与分母 | 解读限制 |
|---|---|---|
| `answer_accuracy_pct` | 与完整原题逻辑标签相同 / 所有计划题 | 输出失败也计入；包含未知题 |
| `macro_three_label_accuracy_pct` | 三种标签各自准确率的平均值 | 缺任一种标签时为 null，另报告混淆矩阵 |
| `proof_retention_pct` | 保留后仍能推导正确结论 / 原始可回答题 | 原始未知题不进入分母 |
| `answer_accuracy_given_proof_retained_pct` | 答案正确 / 证明仍完整的原始可回答题 | 各方法分母可能不同，不能直接当作公平主比较 |
| `proof_supported_correct_pct` | 标签正确且所引用句子可推导该结论 / 原始可回答题 | 接受充分证据的超集与不同合法证明；不是引用精简度 |
| `visible_context_accuracy_pct` | 回答匹配实际可见上下文的逻辑状态 / 所有计划题 | 因压缩丢前提而正确拒答仍可能在原任务上失败 |
| `all_three_worlds_correct_pct` | 三个配对世界都答对 / 完整三元组 | 未完整安排的组单列；已安排但漏回的题计错 |

所有百分率均为 0–100；零分母为 null/undefined。JSON 给出分母、标签分布、错误计数和 template_depth 分层。

`proof_depth` 是原始可回答题的最短规则推导深度：事实为 0，合取规则为 1 + 各前提深度的最大值。未知没有证明，深度为 null；`template_depth` 只是它来自哪一级构造模板，不能称作“未知结论的证明长度”。

现有 `joint_exact_evidence` 仍为精确集合代理；新增 `proof_supported_correct` 在这个形式片段内接受任何足以证明结论的可见引用集合。全文全引也可能获得支持分，因此必须单列引用数量、冗余与可读性，不能把它宣传为优质引用率。

压缩后必要证据丢失的题，应区分“丢证据且答错”和“丢证据但猜对”；证据完整仍答错也可能由格式或基础设施错误造成。报告是错误定位工具，不能单凭它断言模型内部逻辑能力的因果变化。

## 5. 它如何服务 WWW 方法论文

核心问题仍是：**同模型、同检索结果、同预算下，压缩是否保住完成任务所需的条件和推理前提？** 受控演绎集提供机制诊断；自然网页 pilot 与公开任务提供外部有效性，两者分别报告。

`closure` 仍使用既有英文规则依赖，不读取符号金标图。当前条件词/邻段规则很可能抓不到跨文档规则链；如果诊断暴露这一点，应记录为方法局限，再设计只从公开文本预测依赖的改进。不能把评测用的 oracle 悄悄接进压缩器，也不能把其成绩作为可部署方法效果。

已有 RuleTaker、ProofWriter 等相关路线。这里增加的是与压缩预算关联的诊断工具，不据此声称提出全新的逻辑推理 benchmark。官方数据、许可、版本、任务提示与指标仍未适配；FOLIO 等更广逻辑任务可作为后续候选，但不得把本工具的分数叫作它们的官方成绩。

建议下一轮：选定真实模型 → 完整输入下验证标签/深度表现 → 固定预算压缩对照 → 核对证明保留与错误原因 → 接入更强基线及自然网页 → 再据实测修改论文。当前没有真实模型准确率或方法收益结论。

## 6. 软件验收与可复现生成

```bash
python experiment/deduction.py generate --out work/deduction_new --seed 2026 --families 4 --depths 0 1 2 3 4 --split dev
```

每次写入新目录，保存数据/生成器哈希与清单。符号求解器枚举所有包含意义下最小的支持集合（并非只取最少句子的一个证明），超过搜索/证明数量上限会报错，不输出截断金标。

新增 12 项测试检查合取、否定、未知、无逆推、循环、不同证明、证明深度、独立参考推导、金标隔离、文本错配、引用支持、缺失与成对统计。全项目 **46 项测试通过**。测试中人为构造的回答仅保存在忽略的 work/，不充当模型成绩。
